# Hotel Booking System: запуск в Postman

В этой папке находятся коллекция из 68 запросов и шаблон окружения для ручного запуска.
Готовый запуск из IDEA сам подготавливает заполненное окружение, ключи и demo-пароли.
JWT, ID, requestId, даты и данные для регистрации коллекция получает сама.

## Готовый запуск на Mac через IDEA

1. Скачай актуальную версию проекта. При обновлении существующего checkout сначала
   сохрани свои локальные изменения, затем выполни `git pull --ff-only` в ветке `main`.
   Открой корневую папку `hotel-booking-system` через **File → Open**.
2. Если IDEA спрашивает, доверься проекту и выбери **Load Maven Project**. Дождись
   загрузки зависимостей и индексации. Открывай корневой `pom.xml`, а не отдельный сервис.
3. Открой **File → Project Structure → Project**. В поле **SDK** выбери **JDK 21**.
   Если его нет, нажми **Download JDK**, выбери Version **21** и, например, Temurin.
   Для Mac с Apple Silicon нужна архитектура aarch64/ARM64; для Intel — x86_64.
4. В **Settings → Build, Execution, Deployment → Build Tools → Maven → Runner**
   проверь **JRE: Project JDK (21)**. Maven можно оставить **Bundled**: отдельная
   установка Maven для запуска из IDEA не требуется.
5. Останови ранее запущенные конфигурации Discovery, Hotel, Booking и Gateway.
   Нужны свободные порты **8761, 8080, 8082, 8083**.
6. В списке конфигураций сверху выбери **Hotel Booking - Postman** и нажми зелёный
   треугольник **Run**. Конфигурация хранится в `.run/` и появляется после открытия
   корневого проекта. Она использует стандартный Maven runner IDEA.
7. Если конфигурация не появилась, открой **Run → Edit Configurations… → + → Maven**:
   - Name: `Hotel Booking - Postman`;
   - Working directory: корневая папка проекта;
   - Run / Command line: `-N -Ppostman-demo exec:exec`;
   - JRE: Project JDK 21.
   Нажми **Apply → Run**.
8. Дождись строки **ГОТОВО: сервисы запущены, можно запускать Postman**.
   При первом запуске скачиваются зависимости, затем стартуют Discovery → Hotel →
   Booking → Gateway. Не запускай эти сервисы дополнительно вручную. Создавать ключи,
   выставлять профили и заполнять переменные окружения не нужно.
9. Открой Postman Desktop → **Import** и выбери файл коллекции:
   `postman/HotelBooking.postman_collection.json` в корне скачанного проекта.
10. Снова нажми **Import** и выбери **сгенерированный** файл окружения:
    `.local/postman/HotelBooking.ready.postman_environment.json`.
    Полный путь напечатан в консоли IDEA после готовности. `.local` — скрытая папка:
    в диалоге выбора файла на Mac нажми **Cmd+Shift+G** и вставь полный путь из консоли.
    Если Postman предлагает заменить окружение с тем же ID, выбери **Replace**.
    Пустой шаблон `HotelBooking.local.postman_environment.json` для этого способа не нужен.
11. Справа сверху выбери окружение **Hotel Booking — Local**. Пароли в нём уже заполнены.
12. Открой коллекцию **Hotel Booking System — полный последовательный прогон** → **Run**.
    Отметь все семь папок, оставь исходный порядок, **1 iteration**, и нажми **Run**.
    Если Runner показывает отдельный выбор окружения, выбери **Hotel Booking — Local**.
13. Проверь результаты: должно выполниться не менее **68 запросов**, все проверки —
    зелёные, Failed — **0**. При ожидании операции число запросов может быть больше.
    Ответы 400/401/403/404/409 в специально названных проверках ожидаемы и дают зелёные Tests.
14. После проверки нажми **Stop** в IDEA. Конфигурация останавливает свои четыре JVM
    и удаляет временную пару ключей. Логи остаются в `.local/postman/run.*/`.
    При явной остановке Maven может сообщить о прерывании с кодом 130/143 —
    это результат остановки, а не провал проверок Postman.

При следующем запуске достаточно снова нажать **Run** в IDEA, дождаться **ГОТОВО** и
запустить импортированную коллекцию в Postman. Локальные пароли сохраняются, поэтому
повторный импорт окружения не нужен. H2 создаётся заново при каждом запуске сервисов;
сама коллекция допускает несколько запусков подряд без перезапуска стенда.

Если удалить `.local/postman/passwords` при остановленном стенде, в следующий раз
будут сгенерированы новые пароли — тогда снова импортируй заполненное окружение.
Не добавляй папку `.local/` и заполненное окружение в Git.

## Та же подготовка из терминала

При установленных Java 21, Maven, Bash, OpenSSL и curl выполни из корня:

```sh
mvn -N -Ppostman-demo exec:exec
```

После **ГОТОВО** выполни шаги импорта и запуска Postman выше. Терминал оставь
открытым, для остановки нажми **Ctrl+C**. На Mac Bash, OpenSSL и curl уже входят
в систему. Из IDEA используются настроенный JDK и встроенный Maven.

Автоматический запуск проверяет порты, включает demo только в своих экземплярах,
использует отдельные H2, передаёт приватный ключ только Booking и проверяет обе
спецификации через Gateway. При ошибке старта останавливаются только созданные
им процессы. Локальные файлы с паролями доступны только владельцу.

## Если сервисы уже настроены вручную

1. Подними приложения из IDEA в порядке: **Discovery → Hotel → Booking → Gateway**.
   У Hotel и Booking должен быть активен профиль `demo`; настрой ключи RSA по README проекта.
   `api-support` и `request-context` — библиотеки, отдельно их запускать не нужно.
   Дождись готовности Gateway на `http://localhost:8080`.
2. В Postman нажми **Import** и импортируй оба JSON из этой папки:
   - `HotelBooking.postman_collection.json`;
   - `HotelBooking.local.postman_environment.json`.
3. Выбери окружение **Hotel Booking — Local** в правом верхнем углу.
4. Открой это окружение и укажи текущие локальные значения:

   | Переменная | Что указать |
   | --- | --- |
   | `adminPassword` | Значение `DEMO_ADMIN_PASSWORD` из конфигурации запуска Booking в IDEA |
   | `userPassword` | Значение `DEMO_USER_PASSWORD` из той же конфигурации |

   Имена уже заданы: `demo-admin` и `demo-user`. Если ты менял их в настройках приложения,
   исправь `adminUsername` и `userUsername`. При другом порте Gateway исправь `baseUrl`.
5. Открой коллекцию **Hotel Booking System — полный последовательный прогон** → **Run**.
   Выбери все семь папок, оставь исходный порядок и **1 iteration**, нажми **Run**.
   Если Runner показывает выбор окружения, проверь, что выбрано **Hotel Booking — Local**.

Рекомендуется актуальный Postman Desktop. Для Postman в браузере потребуется Desktop Agent,
чтобы обращаться к localhost. Сценарий рассчитан на Collection Runner: запуск отдельных
запросов кнопкой Send не создаёт общий контекст прогона.

## Что проверяется

- Swagger/OpenAPI через Gateway, вход и регистрация, ответы без пароля.
- JWT и роли USER/ADMIN, скрытие внутреннего API, валидация запросов.
- Создание, чтение и изменение отелей и номеров, недоступные номера и рекомендации.
- Ручное бронирование, повтор по requestId, конфликт параметров и отмена пересекающейся брони.
- Автоподбор свободного номера, история и пагинация, доступ только владельцу брони.
- Статистика загрузки и счётчики, отмена и повторная отмена, освобождение номеров.
- Защита записей с историей от удаления и CRUD временных записей без истории.

Ответы **400, 401, 403, 404 и 409** в соответствующих запросах ожидаемы: смотри результат
вкладки Tests, а не только HTTP-код. При неожиданной ошибке коллекция останавливается.
При ответе 202 она опрашивает состояние раз в секунду до 90 секунд и проверяет итоговый статус.

## Повторный запуск и тестовые данные

Каждый полный запуск создаёт отдельного пользователя, собственный отель и номера с уникальными
именами. ID существующих записей не используются для изменения или удаления. В конце сценарий
отменяет свои бронирования и удаляет дополнительные записи без истории.

Пользователь с историей, основной тестовый отель, его номера и три отменённые брони остаются
в базе: правила проекта защищают историю от удаления. Повторный запуск создаёт новый набор
данных и не требует сбрасывать H2. Если прогон остановился раньше конца, часть его данных и
бронирований может остаться; следующий полный запуск всё равно использует новые данные.

JWT и сгенерированные пароли сохраняются в локальных переменных одного прогона.
В шаблоне окружения оба demo-пароля пустые; автоматический запуск заполняет отдельный
локальный файл. Не публикуй своё заполненное окружение
и отчёты с телами запросов авторизации.

## Если запуск остановился

- Ошибка о `adminPassword` или `userPassword`: выбери окружение и заполни оба значения.
- Ошибка подключения: проверь, что Gateway запущен, и значение `baseUrl`.
- 401 при входе: проверь пароль demo-пользователя и активный профиль `demo` у Booking.
- 401 после входа: проверь, что все проверяющие JWT сервисы используют публичный ключ,
  соответствующий приватному ключу Booking.
- 503: дождись регистрации Hotel и Booking в Eureka и обновления маршрутов Gateway.
- 409 в запросах, где ожидается другой код: открой ответ и первую красную проверку;
  в запланированных проверках конфликтов 409 должен давать зелёные Tests.

Это последовательный HTTP-сценарий. Конкурентные запросы, перезапуски и внедрение сетевых
сбоев проверяются Java/JUnit/Failsafe-тестами проекта.

Коллекция проверена Newman 6.2.1 на четырёх запущенных JVM: два последовательных запуска,
136 запросов, 466 проверок, 0 ошибок. Сервисы собраны из исходников, соответствующих main
`731f558`. Ожидание подтверждения и отмены дополнительно проверено на контролируемых
HTTP-ответах с промежуточными состояниями.

Автоматический стенд дополнительно проверен через `mvn -N -Ppostman-demo exec:exec`
на Linux с JDK 21: финальный прогон — 68 запросов, 233 проверки, 0 ошибок.
Проверены сохранение паролей при повторном запуске, отказ при занятых портах,
очистка после ошибки сборки и остановка всех собственных сервисов после завершения
родительского Maven, с освобождением портов и удалением временных ключей.

# Свои бронирования: история, просмотр, отмена

Все публичные операции доступны через Gateway с JWT пользователя (USER/ADMIN).
Владелец определяется только по `sub` токена. ADMIN в этих пользовательских
операциях также видит только собственные бронирования.

## История и просмотр

`GET /api/bookings?page=0&size=20` возвращает `content` (список BookingResponse),
`page`, `size`, `totalElements`, `totalPages`. По умолчанию page=0, size=20;
page >= 0, size от 1 до 100. Неверные границы дают 400. Порядок: createdAt DESC,
затем id DESC. Пустая история или страница за концом выборки возвращает пустой
content, а не ошибку.

`GET /api/bookings/{id}` возвращает 200 и BookingResponse владельца.
Несуществующая и чужая запись одинаково возвращают 404, включая попытку отмены.
Передача username/userId в параметрах не позволяет изменить владельца запроса.

## Отмена

`DELETE /api/bookings/{id}` не требует тела:

| HTTP | Результат |
|---|---|
| 200 | CANCELLED: Hotel подтвердил освобождение |
| 202 | Отмена сохранена и ещё выполняется; cancellationRequested=true |
| 404 | Бронирование отсутствует или принадлежит другому пользователю |

BookingResponse дополнен `cancellationRequested`. При недоступности Hotel
подтверждённая бронь остаётся CONFIRMED с этим флагом: это не означает, что слот
уже освобождён. История и GET показывают текущий результат. После успешной
отмены статус становится CANCELLED, флаг сбрасывается. Повтор DELETE возвращает
тот же итог без повторного удалённого действия. Для повторного бронирования
используется новый requestId.

Намерение отмены фиксируется в локальной транзакции до HTTP-вызова. Новый
внутренний cancel в Hotel допускает HELD/CONFIRMED -> RELEASED, безопасен при
повторе и сохраняет запрет для позднего reserve/confirm. Накопительный timesBooked
не уменьшается. Компенсационный release по-прежнему не освобождает CONFIRMED.

Внутренние маршруты, доступные только SERVICE JWT:

- POST `/internal/reservations/{bookingId}/cancel` с исходными roomId и датами;
- POST `/internal/auto-reservations/cancel` с bookingId, hotelId и датами.

Отмена до резервирования сохраняет RELEASED-маркер, в том числе до выбора номера
при autoSelect. Позднее подтверждение не возвращает локальный CANCELLED в
CONFIRMED. При потере ответа Booking читает Hotel; неизвестный результат остаётся
незавершённым. При сбое локальной фиксации или сети фоновый обработчик повторяет
отмену по сохранённому намерению, включая записи со статусом CONFIRMED.

HTTP-вызовы выполняются вне транзакций БД. Ограниченные повторы и расписание
восстановления описаны в [Saga](booking-saga.md). Ограничение H2 in-memory на
сохранность данных после остановки процесса остаётся в силе.

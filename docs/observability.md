# Корреляция запросов и логи

Gateway, Booking и Hotel используют общий Java-модуль request-context.
Входной заголовок X-Correlation-Id принимается, если он содержит 1–64 символа
из A–Z, a–z, 0–9, точки, дефиса и подчёркивания. Для отсутствующего, некорректного
или повторённого заголовка создаётся новый идентификатор. Выбранное значение
передаётся backend и возвращается клиенту в X-Correlation-Id, включая ответы
security-фильтров, 404/503 и повторные ERROR/ASYNC dispatch.

На время обработки идентификатор находится в MDC под ключом traceId. По завершении
или исключении предыдущий MDC восстанавливается. Остальные ключи MDC сохраняются.
Gateway передаёт заголовок через прокси, RestClient Booking добавляет тот же ID
во все вызовы Hotel, включая retry, confirm, status, release и cancel.

Gateway, Booking и Hotel выводят структурные JSON-логи в формате ECS средствами
Spring Boot: logging.structured.format.console=ecs. HTTP-событие содержит метод,
путь без query string, статус и durationMs; MDC добавляет traceId. Тела запросов,
пароли и Authorization этим механизмом не логируются.

Фоновый проход Saga создаёт отдельный traceId для каждой обрабатываемой записи.
Он сохраняется при её удалённых вызовах и обработке ошибки, затем очищается.
Новый фоновый проход получает новый traceId, а bookingId связывает все попытки
одного бронирования с исходными HTTP-вызовами. Это корреляция приложения через
X-Correlation-Id; поддержка W3C traceparent и экспорт в OpenTelemetry не заявляются.

Пример запроса:

```sh
curl -i -H 'X-Correlation-Id: demo-request-1' http://localhost:8080/api/hotels
```

Ответ 401 также содержит выбранный ID; соответствующие HTTP-события можно найти
по traceId=demo-request-1. Для успешного запроса добавьте пользовательский JWT.
Для локального текстового вывода можно явно переопределить настройку structured
logging; идентификатор продолжит передаваться в HTTP и храниться в MDC.

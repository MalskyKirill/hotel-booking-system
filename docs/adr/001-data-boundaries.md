# ADR 001. Данные принадлежат сервису

Статус: принято. Дата фиксации: 2026-11-02.

## Контекст

Требуются самостоятельные приложения и отдельные H2 Booking/Hotel. Формулировка
о занятости по BOOKINGS не должна приводить к общей БД или JPA-связи между сервисами.

## Решение

Booking хранит users и booking; Hotel — каталог, room_reservations и операции
автоподбора. Между сервисами передаются обычные ID. bookingId в Hotel не является
FK на Booking. Проверка пересечений в Hotel использует локальные резервы,
представляющие согласованное протоколом состояние занятости.

Сохранены SQL-имена booking, hotels.hotel_name и rooms.room_number вместо
bookings/name/number из примеров ТЗ. Дополнительные поля и таблицы поддерживают
идемпотентность, отмену и восстановление; минимальная предметная модель сохранена.

## Последствия

Нет общей транзакции или проверки занятости через сетевой запрос Hotel → Booking.
Для согласованности требуется Saga и сверка результата. Косметическое
переименование таблиц не оправдывает изменение модели. Потеря H2 одной из JVM
теряет данные соответствующего сервиса; восстановление после этого не обещается.
См. [словарь и ER](../data-model.md).

# ADR 005. JWT, роли и отдельные регистрация и вход

Статус: принято. Дата фиксации: 2026-11-02.

## Контекст

Бизнес-сервисы доступны напрямую и через Gateway. Регистрация и выпуск токена
уже являются разными операциями API; примеры ТЗ объединяют их.

## Решение

Booking подписывает RS256 внешним приватным ключом. Gateway, Booking и Hotel
самостоятельно проверяют подпись, issuer и время. USER/ADMIN ограничиваются
маршрутами; ADMIN дополнительно проверяется методной авторизацией в сервисах.
Booking сверяет текущую роль администратора с локальной БД. Пользовательский JWT
действует один час, пароль хранится как BCrypt-хеш.

Внутренний SERVICE JWT действует пять минут, требует sub=booking-service и
aud=hotel-service и не предоставляет права USER/ADMIN. Gateway не публикует
/internal/**. Только Booking получает приватный ключ; остальные проверяющие
приложения получают тот же публичный ключ.

POST register создаёт USER и возвращает 201 с id/username/role без JWT и без
Location на отсутствующий публичный профиль. POST login отдельно возвращает
accessToken, tokenType, expiresIn. Сохраняются /api/auth/register и /api/auth/login
вместо примерных /user/register и /user/auth. Администрирование — /api/admin/users.

## Последствия

Gateway отказывает до проксирования, но не заменяет защиту сервисов. Изменение
роли/пароля не отзывает ранее выданный JWT в Hotel/Gateway до истечения срока.
Немедленный распределённый отзыв, refresh-токены и ротация без перезапуска не
реализованы. Demo-пароли и приватные ключи не включаются в Git.

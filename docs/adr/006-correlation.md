# ADR 006. Корреляция HTTP и фоновых попыток

Статус: принято. Дата фиксации: 2026-11-02.

## Контекст

Для расследования потерянных ответов нужны связанные события Gateway, Booking
и Hotel; фоновые попытки проходят уже без исходного HTTP-запроса.

## Решение

request-context валидирует/создаёт X-Correlation-Id, возвращает его клиенту,
помещает traceId в MDC и передаёт исходящим RestClient. После обработки и
исключений предыдущий MDC восстанавливается. Gateway и бизнес-сервисы используют
ECS JSON; HTTP-статус и переходы Circuit Breaker представлены вложенными полями.
Фоновая попытка получает новый traceId, bookingId связывает её с прежними.
При отказе Gateway backend-события не возникает, потому что вызов не отправлен.

## Последствия

Логи связывают клиентский запрос и восстановление без общей БД и трейсинг-сервера.
Это не OpenTelemetry trace со span и экспортом, W3C traceparent не поддерживается.
Клиентский ID не является идентичностью пользователя; секреты и тела запросов
механизмом корреляции не логируются. [Формат и правила](../observability.md).

# ADR 003. Saga и неизвестный результат

Статус: принято. Дата фиксации: 2026-11-02.

## Контекст

Ответ HTTP может потеряться после фиксации Hotel. Timeout не доказывает отказ;
немедленный CANCELLED мог бы сообщить об освобождении реально занятого номера.

## Решение

Последовательность локальных транзакций: Booking PENDING → Hotel HELD → Hotel
CONFIRMED → Booking CONFIRMED. HTTP не держит транзакцию БД открытой. При отказе
сохраняется намерение компенсации и читается Hotel: CONFIRMED восстанавливается,
RELEASED завершает отмену, HELD освобождается. Компенсационный release не снимает
CONFIRMED. Для пользовательской отмены существует отдельный cancel.

RELEASED-маркер можно сохранить до reserve: запоздавший запрос не восстановит HELD.
При неизвестном результате остаётся PENDING/202 либо cancellationRequested=true
и 202 для отмены. Планировщик завершает операцию после восстановления связи.
GET только читает состояние. Таймауты и ограниченные retry с backoff обёрнуты
Resilience4j Circuit Breaker; 4xx и бизнес-отказы не открывают цепь.

## Последствия

Клиент после 202 проверяет GET/историю и не считает слот освобождённым заранее.
Потерянное подтверждение может привести к восстановлению CONFIRMED, а не откату
успешного резерва. Это уточняет упрощённое правило ТЗ «любой timeout → CANCELLED».
Необходимы сохранность БД и наблюдение за незавершёнными операциями; постоянная
ошибка доступа требует исправления конфигурации. [Состояния и параметры](../booking-saga.md).

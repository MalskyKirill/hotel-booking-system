## Исправления, найденные при проверке запуска

- Для loopback-demo явно задан тот же адрес в Eureka, что и server.address.
  Иначе имя контейнера могло вести на интерфейс, который локальный процесс не слушает.
- Сервисы ожидают готовность предыдущего, локальные discovery-интервалы сокращены;
  при остановке Eureka остаётся живой до завершения клиентов.
- HotelReservationClient учитывает IllegalStateException транспортной цепочки:
  Spring Cloud выбрасывает его, когда discovery не нашёл экземпляр Hotel.
  Раньше исключение выходило как 500. Теперь оно попадает в существующие retry,
  Circuit Breaker и Saga, сохраняя PENDING/202 или намерение отмены.
- [HotelDiscoveryUnavailableIntegrationTest](../booking-service/src/test/java/ru/mephi/integration/HotelDiscoveryUnavailableIntegrationTest.java)
  использует настоящий Spring Cloud LoadBalancer с пустым SimpleDiscoveryClient,
  настоящие ключи/JWT и H2, без HTTP-мока. Два варианта проверяют ручной режим,
  автоподбор, прежний ID при повторе и отложенную отмену. Цепь отключена только
  в этом изолированном сценарии; включённая цепь проверяется другими тестами.

## Известные ограничения и решения

1. H2 и реестр Eureka находятся в памяти. После остановки JVM данные теряются;
   фоновое восстановление рассчитано на сохранность БД.
2. Конкурентные серии проверяют один экземпляр каждого сервиса. Производственный
   RPS/SLA, длительный стресс и горизонтальное масштабирование не подтверждены.
3. timesBooked считает подтверждения, включая позднее отменённые. Балансировка
   не оптимизирует выручку или число ночей; новые кандидаты позади курсора могут
   попасть только в следующий вызов.
4. Смена роли/пароля не отзывает выданные JWT в Gateway/Hotel немедленно; срок
   пользовательского токена — час. Refresh, denylist и ротация без перезапуска отсутствуют.
5. Локальный demo использует HTTP и доверенную Eureka. Production TLS/mTLS,
   секрет-хранилище и постоянные БД требуют отдельного развёртывания и проверок.
6. История и маркеры идемпотентности не очищаются автоматически, TTL не задан.
   Удаление пользователей/номеров с историей ограничено сервисами.
7. Рекомендации в Hotel, локальные резервы вместо общей BOOKINGS, SQL-имена,
   отдельные register/login и 202 при неизвестном исходе — принятые решения,
   подробно объяснённые в [ADR](adr/README.md).

## Повторение проверки

Из чистого checkout выполните сборку и demo по [README](../README.md). Затем
остановите demo и выполните полный Maven-прогон. Для отдельного диапазона портов:

```sh
mvn -B -ntp -Psystem-tests -Dsystem.base-port=20080 clean verify
```

[CI](../.github/workflows/verify.yml) выполняет полный профиль для PR/push в main,
доступен workflow_dispatch. Отчёты и логи сохраняются как verification-reports
на семь дней. Наличие workflow не означает успешный удалённый прогон новой ветки:
его статус проверяется отдельно после отправки на GitHub.

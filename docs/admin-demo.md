# Администрирование и демонстрационные данные

Все маршруты ниже доступны через Gateway и требуют ADMIN JWT. Контроллеры и
сервисы дополнительно защищены методной авторизацией. USER/SERVICE получают 403,
запрос без JWT — 401. Нумерация страниц начинается с 0, размер по умолчанию 20,
допустимо 1–100.

## Номера

| Метод и путь | Назначение |
|---|---|
| GET `/api/admin/rooms?hotelId=1&page=0&size=20` | Все номера, включая недоступные; hotelId необязателен |
| GET `/api/admin/rooms/{id}` | Номер по ID |
| POST `/api/admin/rooms` | Создание: hotelId, roomNumber, capacity, price |
| PUT `/api/admin/rooms/{id}` | Изменение: roomNumber, capacity, price, available |
| DELETE `/api/admin/rooms/{id}` | Удаление без истории резервирования |

Успешное создание возвращает 201, изменение/чтение — 200, удаление — 204,
отсутствие — 404, конфликт уникальности или запрет удаления — 409.
roomNumber уникален внутри отеля. При обновлении нельзя менять отель, ID или
timesBooked. available=false запрещает новые бронирования, но сохраняет старые.
Изменение и удаление блокируют ту же строку номера, что и резервирование.
Даже RELEASED сохраняет историю и запрещает физическое удаление номера;
для вывода из эксплуатации используется available=false.

Старые маршруты CRUD отелей и POST `/api/rooms` сохраняются.

## Статистика

`GET /api/admin/rooms/statistics?startDate=2027-01-01&endDate=2027-01-08&hotelId=1`

hotelId необязателен, доступны page/size. Даты обязательны, startDate < endDate.
Поля строки: roomId, hotelId, roomNumber, available, timesBooked, periodNights,
heldReservations, confirmedReservations, heldNights, confirmedNights,
confirmedOccupancyPercent. Список возвращается в content со стандартными полями
page/size/totalElements/totalPages.

Ночи учитываются только внутри полуоткрытого периода. HELD отражается отдельно,
RELEASED исключён. Процент загрузки = confirmedNights / periodNights × 100,
с округлением до двух десятичных знаков. timesBooked — накопительное число
подтверждений за всё время; отмена его не уменьшает. Недоступные номера остаются
в статистике. Данные резервов выбранной страницы читаются одним запросом.

## Пользователи

| Метод и путь | Назначение |
|---|---|
| GET `/api/admin/users?page=0&size=20` | Список пользователей |
| GET `/api/admin/users/{id}` | Пользователь по ID |
| POST `/api/admin/users` | Создание: username, password, role (USER/ADMIN) |
| PATCH `/api/admin/users/{id}` | Изменение password и/или role |
| DELETE `/api/admin/users/{id}` | Удаление без истории бронирований |

Логин неизменяем: он является sub JWT. Пароли хешируются BCrypt, в ответах
присутствуют только id/username/role. Пароль должен содержать минимум 8 символов,
не быть пустым и занимать максимум 72 UTF-8 байта. Пустой PATCH даёт 400.
Регистрация через публичный auth API по-прежнему назначает только USER.

Пользователь с любой историей бронирований не удаляется (409). Последний ADMIN
не может быть удалён или понижен до USER (409). Изменения администраторов
сериализуются блокировками с повторным подсчётом текущих ролей.

Booking дополнительно сверяет актуальную роль администратора в своей БД.
Смена роли/пароля сама по себе не отзывает уже выданные JWT: Hotel продолжает
проверять роль из токена до его истечения (срок — один час). Для использования
новых прав нужно войти заново. Немедленный распределённый отзыв токенов здесь
не реализован.

## Профиль demo

В обычном профиле данные и пользователи автоматически не создаются.
Для обоих бизнес-сервисов активируйте demo через свойство spring.profiles.active.
До исправления передачи CLI-аргументов используйте JVM-параметр
`-Dspring.profiles.active=demo` перед `-jar` либо SPRING_PROFILES_ACTIVE.

В Booking задайте значения безопасно через переменные окружения:

- DEMO_ADMIN_PASSWORD — пароль demo-admin;
- DEMO_USER_PASSWORD — пароль demo-user.

Пароли не заданы в репозитории и не выводятся в логи. Имена можно изменить через
DEMO_ADMIN_USERNAME и DEMO_USER_USERNAME. Получите токен через обычный
POST `/api/auth/login` с выбранными credentials. Профиль создаёт ADMIN и USER,
сохраняет существующие пароли и не повышает роль уже существующего аккаунта
молча. Недостающие/невалидные пароли не позволяют запустить demo-профиль.

Hotel заполняет только пустую БД: два отеля, по три номера, два номера выключены
из эксплуатации. Повторный запуск загрузчика не дублирует и не перезаписывает
данные. Резервы не предзаполняются: их можно создать через обычную Saga и затем
проверить изменение статистики. Используются внешние RSA-ключи, как при обычном
запуске; закрытый ключ не включается в Git. H2 in-memory теряет данные после
остановки процесса.
